# 2025-07-31 — PyAV mobile-forge recipe

Created PyAV (av 18.0.0) mobile-forge recipe — a two-part chain:

## flet-libffmpeg (8.1.2)
- `recipes/flet-libffmpeg/meta.yaml` — FFmpeg source, static (iOS) / shared (Android)
- `recipes/flet-libffmpeg/build.sh` — cross-compile FFmpeg configure: iOS as darwin+static, Android as linux+shared
- Key design: disables asm on iOS (Apple asm compatibility), 16KB page-aligned on Android
- Keeps pkgconfig .pc files for downstream resolution

## av (18.0.0)
- `recipes/av/meta.yaml` — PyPI sdist, script_env FFMPEG_DIR={platlib}/opt
- `recipes/av/patches/mobile.patch` — adds os.environ.get("FFMPEG_DIR") before pkg-config fallback in setup.py
- `recipes/av/tests/test_av.py` — smoke tests: import, codec registry, Codec lookup, VideoFrame create
- requirements.host: flet-libffmpeg (promoted to Requires-Dist for Android .so bundling)

## Build order (untested yet)
1. `forge iphonesimulator:arm64 flet-libffmpeg`
2. `forge iOS flet-libffmpeg`
3. `forge android:arm64-v8a flet-libffmpeg`
4. `forge android flet-libffmpeg`
5. Then repeat for `av`

## Caveats
- FFmpeg is a huge build; expect long build times per slice
- iOS ARM asm is disabled; can be enabled after verifying clang integrated assembler compatibility
- The `platform.system() != "Windows"` path in setup.py would hit pkg-config if FFMPEG_DIR is unset; our env var + forge's PKG_CONFIG_LIBDIR should handle this

## 2025-07-31 #2 — Fix CI download timeout

flet-libffmpeg `source.url` was `https://ffmpeg.org/releases/ffmpeg-{{ version }}.tar.gz`.
GitHub Actions runner timed out connecting to ffmpeg.org (SSL handshake).

**Fix:** switched to GitHub archive mirror:
`https://github.com/FFmpeg/FFmpeg/archive/refs/tags/n{{ version }}.tar.gz`

This is always reachable from GitHub Actions. Forge tarfile extraction with strip=1 handles
the `FFmpeg-nX.Y.Z/` directory name just fine — no build.sh changes needed.

## 2025-07-31 #3 — Fix build.sh execute permission

`build.sh` created on Windows had no execute bit. Forge's `compile()` runs `build.sh`
directly as an executable (not `bash build.sh`), so it needs `+x`.

**Fix:** `git update-index --chmod=+x recipes/flet-libffmpeg/build.sh`

## 2025-07-31 #4 — Fix x86_64 Android asm failure

x86/x86_64 architectures require nasm/yasm assembler (not bundled in CI runner).
ARM architectures use inline asm via the C compiler.

**Fix:** Added `case` block to set `asm_arg="--disable-asm"` for x86/x86_64.

## 2025-08-04 — Fix Android runtime "libavformat.so.62 not found"

**Root cause:** `build.sh` used `--target-os=linux` for Android, which makes FFmpeg
create versioned shared libraries with sonames like `libavformat.so.62`. The
serious_python Android packager only collects `*.so` files into jniLibs —
`libavformat.so.62` is left out of the APK, causing dlopen failure at runtime.

**Fix:** Changed `target_os="linux"` → `target_os="android"` in build.sh.
FFmpeg's configure has a dedicated `android)` case that:
- `SLIB_INSTALL_NAME='$(SLIBNAME)'` → installs as `libavformat.so` (no version)
- `SLIB_INSTALL_LINKS=` → no symlinks
- `SHFLAGS='-shared -Wl,-soname,$(SLIBNAME)'` → soname is `libavformat.so`
- `disable symver` → no GNU symbol versioning

Both `flet-libffmpeg` (build 2) and `av` (build 2) need rebuilding — av was
previously linked against `libavformat.so.62` and must re-link to `libavformat.so`.
